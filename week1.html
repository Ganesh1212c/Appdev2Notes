🔁Review of MAD-I

01

An app has a frontend and a backend that talk by request and response.

WhyEverything later (JavaScript, Vue, APIs) plugs into this frontend and backend picture.

  • App: a program that lets a user do something useful (order food, check marks).
  • Frontend: what you see and touch (pages, buttons, forms).
  • Backend: stores data, holds the logic, links the data together.
  • Frontend asks (request), backend answers (response): a client-server design.
  • Why web: every device has a browser, a simple page takes a few lines, and the same idea grows into huge systems.
  • Think restaurant: menu and waiter = frontend, kitchen = backend. You send an order, food comes back.
From the slides

What is an app (at least in our context):

  • An application or program used for interacting with a computing system
  • Allow the user to perform some tasks useful to them

Components:

  • Backend: Store data, processing logic, relation between data elements etc.
  • Frontend: User-facing views, abstract for machine interaction
  • Naturally implies a client-server or request-response type of architecture

Why Web:

  • Close to universal platform with clear client-server architecture
  • Low barrier to entry - trivial to implement simple pages and interaction
  • High degree of flexibility - possible to implement highly complex systems

The frontend asks with a request. The backend answers with a response.

🕰️Origins

04

A quick 1995 glue language that grew up.

WhyThe history explains the quirks you will meet: a language built in a hurry, and built to forgive.

  • Made in 1995 for the Netscape Navigator browser, in a hurry.
  • Meant as glue: small scripts that stick modules from other languages together. Not meant for much code.
  • Named after Java (hugely popular then). It was meant to help Java applets (small programs inside a web page). Two different languages. Trademark issues and name changes followed.
  • Early issues: Slow Limited capability
  • Think glue in a craft box: not the main material, it just holds pieces together.
From the slides

    • Not really meant for much code
  • Primarily meant to assist “applets” in Java - hence JavaScript
    • Trademark issues, name changes, …
  • Issues:
    • Slow
    • Limited capability

Marketing and applets. They are two different languages.

⚡Power: Ajax

05

Ask the server for a small piece, update only that part.

WhyAjax is why the web can feel like an app. Everything later (APIs, Vue) is built on this one idea.

  • ~2005: Google Maps and Google Suggest. Drag and zoom a map, or see suggestions as you type, with no page reload.
  • The trick: JS quietly asks the server for just what it needs, in the background, and updates only that part of the page. Load only what is needed.
  • Named Ajax (Asynchronous JavaScript and XML) by Garrett, 2005.
  • Asynchronous = the page does not freeze while it waits. XML was the data format then. Today mostly JSON. Same idea.
  • fetch starts the request and returns at once with a promise. .then says what to do when the answer arrives (more on this in Week 2).
  • Result: true web applications that feel like desktop apps. Much more on this later.
From the slides
  • Glue was useful, but…

    • Pan around map, zoom in/out seamlessly - fluid user interface:
    • Load only what is needed!
  • Described and Named Ajax - Garrett 2005
    • Asynchronous Javascript and XML
  • Allowed true “web applications” that behave like desktop applications
  • Evolved considerably since then
    • Much more on this approach moving forward

📜Standardization

06

ECMAScript is the rule book. JavaScript is what you use.

WhyECMAScript versus JavaScript, and what ES6 added, is basic vocabulary for the rest of the course.

  • Browsers must behave the same, so the language needed a shared rule book beyond Netscape.
  • ECMA (European Computer Manufacturers Association) standard 262 = ECMAScript. The new name avoids trademark trouble with Java.
  • In practice: ECMAScript = the language standard (versions). JavaScript = the implementation you use. Recipe and dish.
  • ES6 (ECMAScript 2015): the big upgrade. Added classes, modules, let, const, arrow functions.
  • Since then: one smaller release every year. Feature readiness: a feature is added as soon as it is ready, no giant releases.
From the slides
  • Move beyond Netscape needed
  • ECMA (European Computer Manufacturers Association) - standard 262
  • Subsequently called ECMAScript
    • Avoid trademark issues with Java
  • In practice:
    • Language standard called ECMAScript (versions)
    • Implementation and use: JavaScript
  • Significant changes in ES6 - 2015
    • Yearly releases since then
    • “Feature readiness” oriented approach

Quick checkWhat is ES6?

ES6 = ECMAScript 2015. After it, smaller releases come every year.

🧭What version to use?

07

New features, old browsers: four ways out.

WhyIn real projects you must decide which features you can use. These four options are the standard answers.

  • ES6+ has the modern features (modules, scoping, classes). Some older browsers do not support them.
  • Ignore old browsers: ask users to upgrade.
  • Ship a browser with the app (Electron, e.g. VSCode): you know the exact version.
  • Polyfill: a library that adds a missing feature to an old browser. A patch.
  • Compiler (BabelJS): converts new code into older, compatible code.
  • Backend: Node.js and Deno use JS directly as a scripting language, like Python.
From the slides

Possible approaches:

  • Package browser along with application - useful for limited cases, like VSCode (Electron apps)
  • Polyfills: include libraries that emulate newer functionality for older browsers
  • Compilers: BabelJS - convert new code to older compatible versions

Backend

🧬Implications of JS origins

08

Built fast and forgiving, so it has quirks.

WhyMost JavaScript surprises (silent errors, odd semicolons) trace back to one idea: it was built to forgive.

  • Ease over performance at first. Forgiving: many mistakes fail silently, so debugging is hard. Fix: "use strict"; at the top reports more mistakes.
  • Ambiguous syntax: semicolons are optional (auto-inserted, sometimes wrongly). {} is an object literal or a code block. A function is a statement or an expression.
  • Limited IO: errors are “logged” to the console, a hidden developer panel.
  • Closely tied to the page: DOM APIs.
  • Async + Event Loop: one thing at a time with a to-do queue. Clicks and server replies join it, so waiting never freezes the page. Very powerful.

🌳DOM
10




The browser turns HTML into a tree of objects. JS can change it.


WhyThe DOM is how JavaScript touches the page. Every interactive feature goes through it.


  • DOM (Document Object Model): the structure of the page as a tree in memory. Every heading, paragraph and button is a branch.
  • JS can read and change the tree and the page updates instantly. One of its most powerful abilities.
  • Input (what the user does): clicks, typing in text boxes, mouseover.
  • Output (what JS changes): text, colours and styles, drawing.
  • querySelector finds an element with a CSS selector: "h1" (tag), "#id", ".class". It returns the first match, or null if none.
  • Think family tree: JS walks to any person and changes their name or clothes.


From the slides
  • Document Object Model
    • Structure of the document shown on the browser
  • DOM can be manipulated through JS APIs
  • One of the most powerful aspects of JavaScript
  • Input: clicks, textboxes, mouseover, …
  • Output: text, colours/styles, drawing, ...

🖥️Basic frontend usage
12




Frontend JS lives inside a page and runs top to bottom.


WhyA frontend program does nothing alone and has no starting function. Knowing that avoids the first confusing bugs.


  • Must be invoked from an HTML page (a “Document”). A .js file opened on its own does nothing.
  • No compilation step: the browser runs the code straight away.
  • Loosely structured: no main, no required header or body. The browser reads from top to bottom.
  • Comments: // for one line, /* … */ for many lines.
  • Common slip: a script that runs before its element exists finds nothing. Put the <script> at the end of <body>.

🧮Statements and expressions
14




An expression gives a value. A statement does something.


WhyThe difference decides where code is allowed: arguments, assignments and return values all need expressions.


  • Expression: code that gives back a value: 10, "Hello world", 2 + 3. Use it anywhere a value is needed (a function argument, a maths formula).
  • Statement: an instruction that does something: if, loops, declarations. A standalone action, or it has side effects (changes something).
  • Quick test: if it fits inside console.log( … ), it is an expression.


From the slides
Expression
Piece of code that can be executed to obtain a value to be returned
Anywhere you need a “value” - function argument, math expression etc.
Statement
Piece of code that can be executed
Standalone operation or side effects

console.log(2 + 3) works, so 2 + 3 gives a value. if and for are statements.

🔡Strings
16




Text in Unicode. Length counts 16-bit pieces.


WhyStrings look simple, but length and emoji surprise people, and templates are the clean way to build text.


  • Source code is expected in Unicode: every language and emoji. Most engines use UTF-16: each character is one or two 16-bit pieces.
  • length counts those pieces, so an emoji or rare symbol can look like one character but count as 2. Surprising on non-ASCII words.
  • Variable names in other languages are allowed, but avoid them: keep it readable.
  • Template strings (backticks) put values inside text with ${ }.
  • Quotes: 'hi' and "hi" are the same string. Backticks are the special ones: they allow ${ } and line breaks.


From the slides
  • Source code is expected to be in Unicode
    • most engines expect UTF-16 encoding
  • String functions like length can give surprising results on non-ASCII words
  • Can have variables in other languages!
    • But best avoided… keep readability in mind


Quick checkWhat is "😀".length?
UTF-16 stores this emoji as two 16-bit pieces, and length counts pieces.






🕳️Non-values
17




undefined = not given yet. null = empty on purpose.


WhyMixing up undefined and null is a classic source of bugs and exam questions.


  • undefined: no value given yet. JS uses it by default, e.g. for a variable never set. The default unknown state.
  • null: nothing, on purpose. You set it yourself.
  • Very similar, often interchangeable. Pick a meaning for each and stay consistent.
  • undefined == null is true (loose). === is false (different types).
  • Think form fields: undefined = nobody filled it in, null = someone wrote “not applicable”.


From the slides

⚖️Operators and comparisons
18




Coercion converts types quietly. Prefer ===.


WhyA wrong comparison silently takes the wrong branch. Using === avoids a whole family of bugs.


  • + - * / work on numbers. + also joins strings.
  • Rule: + joins when either side is text. - * / always turn both sides into numbers. Text that is not a number becomes NaN (“not a number”).
  • Coercion: JS converts one type into another so the operation can work. Handy, but it can cause surprises. Needs care
  • Loose == converts types first, then compares. Strict === compares with no conversion.
  • Comparisons decide which if path runs and when a loop stops. A wrong one means a wrong decision.
  • Habit: use === almost always.

📦Variables and scoping
19




Declare with let or const. A smaller scope is safer. Avoid var.


WhyScope bugs (a variable changed from far away) are hard to find. let and const keep variables local.


  • A variable is a labelled box for a value. Any non-reserved identifier can be one.
  • Unlike Python, you must declare it (let or const). Unlike C, you need not declare the type.
  • Scope: where it can be seen. Everywhere, or one small area? Smaller is safer: fewer parts can change it by accident. Namespaces group related names under one label so they do not clash.
  • A block is any code between { }, such as the body of an if or a loop. let and const stay inside their block.
  • var is the old way: it only respects function boundaries, so it leaks out of blocks like if and for. Avoid var

🔀Control flow
21




Choose, repeat, skip, stop, pick one of many.


WhyThese few words are the whole vocabulary for making a program choose and repeat.

⚙️Functions and notation
22




Reusable blocks of code. Three ways to write one.


WhyFunctions are JavaScript's main building block, and later weeks pass them around constantly (callbacks, map, Vue).


  • A function is a reusable block, like a recipe you write once and use many times.
  • It takes inputs: parameters when you define it, arguments when you call it. It does work and gives back an answer.
  • Functions are objects: store them in variables, pass them to other functions, assign them like any value.
  • Regular declaration (statement): the oldest way. Callable even above the line where it is written.
  • Named variable (expression): a function stored in a variable. Works only after that line.
  • Arrow function (expression): shortest. One expression and no braces: the result is returned automatically.
  • No return means the function gives back undefined. An arrow with braces { } needs its own return.


From the slides
Reusable block of code
Can take parameters or arguments and perform computation
Functions are themselves objects that can be assigned!
Function Notation
  • Regular declaration: function add(x, y) { return x + y; } // Statement
  • Named variable: let add = function(x, y) { return x + y; } // Expression
  • Arrow function: let add = (x, y) => x + y; // Expression


Quick checkWhich kind of function can you call above the line where it is written?
A regular declaration is a statement and is ready from the start. The other two work only after their line.






🎭Anonymous functions and IIFEs
23




A function with no name, and the old trick to run it at once.


WhyYou will meet IIFEs in older code and in exam questions, so recognise them even though you should not write them.


  • An anonymous function has no name. Store it in a variable or hand it straight to something else.
  • An IIFE (Immediately Invoked Function Expression): an anonymous function wrapped in brackets and run on the spot.
  • Why: old JS had no good scoping. Wrapping code in a function made a private room, so variables did not leak.
  • Today let, const and modules do that job. IIFEs are rare and hard to read. Avoid IIFEs in modern code


From the slides
Why?
Older JS versions did not have good scoping rules.
Avoid IIFEs in modern code - poor readability
  • Anonymous bound: let x = function () { return "hello" }
  • Declare and invoke: (function () { return "hello" }())


Quick checkWhy did people write IIFEs in older JavaScript?
A function created a private room. Now let, const and modules do it.

Listen for the user (input). Change the page (output).


WhyThis pattern, listen then update, is exactly what Vue automates in Week 4.


  • console.log writes only to the hidden developer console. Fine for checking your own work, not for production: real users never see it. (Variants exist, e.g. for error logging.)
  • JS was designed for document manipulation. Also keep in mind: Flask is a backend framework, VueJS is a frontend framework.
  • Input from the DOM: mouse, text, clicks. Listen for them.
  • Output to the DOM: change text, colours and more.
  • addEventListener("click", fn) means: when a click happens, run fn. That function is a callback.
  • input.value reads what the user typed. textContent sets plain text (no HTML is parsed).
  • Think doorbell: it listens for a press (input), then plays a sound (output).
