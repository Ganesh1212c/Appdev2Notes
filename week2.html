📚Arrays

01

An ordered list that can hold anything.

WhyArrays are the default container for lists of data, and most array questions are about length and holes.

  • Any types, even mixed: numbers, strings, objects, functions.
  • Index starts at 0. length = highest index + 1.
  • Holes: skipped slots are empty but still count in length. A hole is not a stored undefined: reading either gives undefined, but 5 in a is false for a hole.
  • Multi-dimensional: an array of arrays, read as grid[row][col].
  • Walk through it with for…of (next card).
From the slides
  • Collection of objects of any type
    • Can even be mixed type (numbers, strings, objects, functions…)
  • Element access
  • Length
  • Holes
  • Iteration

Quick checkconst a = [1, 2, 3]; a[5] = 9; What is a.length?

Index 5 is the last slot, so length is 6. Slots 3 and 4 are holes.

🔁Iteration

02

Go over every item, one by one.

Whyfor…of works on any iterable, so one loop style handles arrays, strings, Maps and Sets.

  • Iterable: you can read its items in order. Array, String, Map, Set, DOM tree.
  • Iterator: the pointer to the next item. for…of drives it for you.
  • A plain object is not iterable. Use Object.keys / values / entries.Case matters: Object.keys, not object.keysRemember: for…of gives values, for…in gives keys.
From the slides
  • Go over all elements in a collection
  • Concepts:
    • Iterable: an object whose contents can be accessed sequentially
    • Iterator: pointer to the next element
  • Iterable objects: Array, String, Map, Set, Browser DOM - tree structure
  • Objects: object.keys(), object.entries() - helper functions

Quick checkfor (const x of { a: 1 }) {} What happens?

Plain objects are not iterable. Use Object.entries(obj) instead.

🧪map, filter, find

03

Functions that take a function. Chain them to transform data.

Whymap, filter and find replace most hand-written loops, and a chain of them reads like a sentence.

  • Callback: a function you pass in. The other function calls it back.
  • map: change every item. New array, same length.
  • filter: keep items where the callback is true. New array.
  • find: first item where it is true, else undefined.
  • The callback also receives the index: (item, index).
  • The original array never changes. Chain them: each output feeds the next.

Callback: important concept - function passed in to another function, to be called back for some purpose

map keeps every item and replaces it with the callback result. To keep only 2 and 3 you would use filter.






🗺️Maps, WeakMaps, Sets
04




Better containers than a plain object or array.


WhyA Map or Set is the right tool when a plain object or array would force workarounds.


  • Map: a real dictionary. Any value can be a key (even an object). Keeps insertion order. Has .size.
  • Plain object keys are always strings. Map keys are not.
  • Set: every value appears once. Duplicates are dropped.
  • WeakMap: keys must be objects and are held weakly (can be garbage-collected). Not iterable, no size.Advanced: use only if needed


From the slides
  • Maps: proper dictionaries instead of objects
  • WeakMaps
  • Sets
More advanced topics - use only if needed


Quick checkWhat is new Set([1, "1", 1]).size?
1 and "1" are different values, but the second 1 is a duplicate. So 2.

05




Unpack an array or object into variables in one line.


WhyIt shortens code you write all the time: unpacking function results and options.


  • Arrays match by position. Skip with an empty slot, collect the rest with ...rest.
  • Objects match by name. = value sets a default.
  • Makes passing and collecting arguments easier.


From the slides
  • Simple syntax to split an array into multiple variables
  • Easier to pass and collect arguments etc.
  • Also possible for objects


Quick checkconst [x, , y] = [1, 2, 3]; What is y?
The empty slot skips the 2, so y gets the third item, 3.

  • Single track: each object has one prototype.


From the slides

🥞Function calls and the call stack
12




Calls pile up. Returns pop off. Last in, first out.


WhyThe call stack explains why only one function runs at a time, and why endless recursion crashes.


  • A function call is like a branch, but JS must remember where to come back to.
  • Call stack: the chain of calls so far. A call pushes a frame, a return pops it.
  • Only the top function runs.



  
Try it: step through the calls

From the slides
  • Function is like a “branch”
    • but must save present state so we can return
  • Call stack:
    • Keep track of chain of functions called up to now
    • Pop back up out of stack
  • main() on stack - current - calls f()
  • f() goes on stack - calls g()
  • g() goes on stack - calls h()
  • h() goes on stack - executes
  • return from h -> pop into g
  • return from g -> pop into f
  • return from f -> pop into main

Quick checkThe stack is main, f, g, h with h on top. Which returns first?
Last in, first out. The top frame finishes first, then control pops back into g.






♻️Event loop and task queue
13




Callbacks wait in a queue until the stack is empty.


WhyThe event loop explains why setTimeout(…, 0) still runs late, and why a long loop freezes a page.


  • Task queue: tasks waiting to run. Clicks, input, network and timers push tasks in.
  • Event loop: waits for the stack to be empty, then moves the next task onto it.
  • Run-to-completion: a task finishes fully before the next one starts.A long loop freezes the page: nothing else can run

📞Why callbacks?
14




Slow work must not freeze everything else.


WhyIt explains the shape of every Node and browser API: start the work, pass a function, carry on.


  • Long-running code (files, network) blocks until it finishes.
  • Fix: start it, let the main code carry on, and call back when it is done.
  • Sync = wait here. Async = carry on, callback later.
  • Node callbacks are error-first: (err, data).


From the slides
  • Long running code
    • Will block execution till it finishes!
  • Push long running code into a separate “thread” or “task”
    • Let main code proceed
    • Call back when completed
Slides 22 and 23 show the two code examples above (reading files: synchronous, then asynchronous).


Quick checkWhy use async readFile instead of readFileSync on a server?
While the file loads, the server keeps handling other requests. The callback runs once the data is ready.

15




Single-threaded, yet fast, because it never waits idle.


WhyPromises and async/await are the modern way to write callbacks, and fetch and Vue use them everywhere.


  • Very powerful: high performance even though JS is single threaded.
  • Can be hard to follow. First use async libraries and functions, write your own later.
  • Promises and async/await: important, but deferred for now.Peek only: not needed yet


From the slides
  • Very powerful - allows JS to have high performance even though it is single threaded
  • Can be difficult to comprehend
    • Focus on using async libraries and functions before writing your own
  • Promises, async function calls etc.
    • Important and useful concepts
    • Deferred for now


Quick checkJS runs on one thread. Why can async code still keep a page responsive?
Slow tasks are started and the code moves on. When they finish, their callbacks join the task queue.

🧾JSON
16




Text that looks like a JS object, but stricter.


WhyJSON is the format almost every API uses, so one JSON mistake can stop a whole app.


  • JavaScript Object Notation: for serialization and communication.
  • Values: string, number, true / false, null, array, object.
  • Keys and strings use double quotes only. No trailing comma, no comments, no functions.
  • The notation is frozen: it will never change, so even annoying rules stay (like no trailing comma).


From the slides
  • Object notation - for serialization, communication
  • Notation is frozen
    • Means even problem cases will remain (trailing “,” etc could be useful but will not be used)
  • Usage through JSON API


Quick checkWhich one is valid JSON?
Only double-quoted keys and strings are allowed.

  • JSON.parse(text): text to object. Throws SyntaxError if the text is invalid.
  • stringify drops functions and undefined values. Pretty print with JSON.stringify(v, null, 2).
