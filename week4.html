⚡Reactivity

01

Change the data and the screen updates itself.

WhyWithout it you hand-write DOM updates for every change. With it you describe the page once.

  • Reactivity: the page auto-updates in response to changes in data.
  • A binding links the model (data) to the view (display). Change one side and the other follows.
  • Focus on what should be shown, not how to update it.
  • Why? User interaction is fundamentally reactive: respond to changes in input. One change can need many screen updates.
  • Example: the user logs in. Navigation adds the logged-in links, the course list updates, colours follow the theme. All from one change of data.
From the slides
  • Auto-update in response to changes in data
  • Binding between model (data) and view (display)

🕰️How did we do it before?

02

Two older ways to keep the screen in step with the state.

WhySeeing the old ways shows exactly what Vue removes: all the manual bookkeeping.

  • Server tracks the state (is the user logged in? what is the date and time?).
  • Server responds with complete HTML built from the present state: different layouts, visibility in views, rendered for each user. Fully server-side.
  • Client JS: a login controller retrieves the user model. Client-side JS goes through each element and updates it as needed (jQuery, vanilla JS).
  • Server-side costs a full page per change. Client JS means you must find and update every affected element yourself, and forgetting one leaves stale data on screen.

🧷Directives and events

03

Special attributes that link HTML to your data and your events.

WhyDirectives are how a Vue template says “show this”, “keep this in sync” and “do that on click” with no DOM code.

  • A directive is a special attribute that starts with v-. {{ }} shows a value as text.
  • v-bind (short :): one-way binding. Update the variable and the display changes. Typing into the element does not change the variable.
  • v-model: two-way binding for inputs, checkboxes etc. (form data). Edit either side and the other follows.
  • v-on (short @): event binding. Run code when something happens: click, input, submit.
  • v-model is for form inputs. For a plain attribute like href or src, use v-bind

🎨Class and style binding

04

Switch CSS classes on and off from data.

WhyInstead of adding and removing class names in JS, you say which classes apply for the current data.

  • Dynamically change an element's class with :class (short for v-bind:class).
  • Special support for an object: { className: condition }. Several classes can be attached at once, based on the key-values.
  • If the value for a key is true, that key is applied as a class (or style). If it is false, it is left out.
  • :style works the same way, with CSS properties as keys.
  • A plain class="…" can sit beside :class. Vue merges them.

👁️Conditional rendering
05




v-if and v-show both hide things. They are not the same.


WhyA favourite exam question. The difference is whether the element still exists in the DOM.


  • v-if="argument": what follows is shown when the argument is true. It is JS-based and changes the DOM: the element is added or removed.
  • v-show="param": shown only if the parameter is true, but it is always rendered and present in the DOM. Only the CSS display property changes.
  • Use v-show for things you switch often (a cheap toggle). Use v-if when it is rarely shown or should not exist at all.

🔁Looping: v-for
06




Repeat an element for every item in a list or object.


WhyLike a Jinja for-loop, but the list stays live: add an item to the data and a new row appears.


  • Iterate over any JS iterable: array, object, string. Usage is similar to Jinja {{ }} templates.
  • v-for="item in items": items is an array.
  • v-for="value in obj": obj is an object (you get each value).
  • v-for="(value, name) in obj": name is the object's key. It is called name because key has another meaning in v-for (next card).
  • v-for="(value, name, index) in obj": index is the numerical position.


From the slides
  • Iterate over any JS iterable
    • Array, Object, String etc.
  • Usage similar to Jinja {{}} templates
  • Examples:
    • v-for="item in items" // items is an array
    • v-for="value in obj" // obj is an object
    • v-for="(value, name) in obj" // name -> key: “key” has another meaning in v-for
    • v-for="(value, name, index) in obj" // index -> numerical index


Quick checkv-for="(value, name) in obj" with obj = { a: 1 }. What is name?
With two names, the second one is the object's key. value is 1.






🔑Loop keys
07




Give each repeated row a unique key so Vue can track it.


WhyWithout keys Vue may reuse the wrong row when the list changes, so things like typed text end up beside the wrong item.


  • Looping creates new DOM elements. When the list changes, Vue needs a way to tell which element is which.
  • Vue compares the old and new virtual DOM (a light copy of the page in memory). This diffing finds the smallest change to show on screen. Vue uses heuristics to minimise the work.
  • For simple updates the heuristics are enough. For complex ones it is hard to tell what has changed and what is new.
  • Provide a key: it must be unique for each loop element. Updating an item with the same key updates only the relevant elements.
  • Rule of thumb: provide a key where possible (an ID, or the index). A stable ID is best: an index breaks when items are inserted or reordered.

    🧩Model and View
    08
    

    

    The model is the data. The view is how it is shown. They do not always match.
    

    WhyReal screens often need extra or derived data that does not belong in the database.
    

    • Model: the “data” of the application, usually stored on the server in a database.
    • View: what is displayed to the end user (or to a non-human consumer). The rendering of the data.
    • Problem: sometimes the view needs more info than the model holds, or there is derived information.
    • Example 1: a form with username, password, repeat_password. Should repeat_password be in the model? Where is it stored and how is it used? (It exists only to check the form, so it is view data, not model data.)
    • Example 2: a page with top comments and top posts. Should top_comments and top_posts be in the model, or derived from other data? What does the displayed information correspond to?

    🪄ViewModel
    09
    

    

    A model for the view: model data plus extra and derived data, bound to the screen.
    

    WhyIt keeps display logic out of both the database model and the HTML, so the code stays clean.
    

    • ViewModel is yet another pattern.
    • Create model constructs with additional data or derived data.
    • Bind them to the view: the view auto-updates when the data changes, and (possibly) the data auto-updates when it is changed in the view.
    • Why: cleaner code.
    

    From the slides
    • Yet another “Pattern”
    • Create model constructs with additional data / derived data
    • “bind” to view
      • Auto update view on change in data
      • (possibly) auto update data when changed in view
    • Why?
      • cleaner code
    

    Quick checkWhat is the main reason to use a ViewModel?
    The ViewModel holds what the view needs and keeps it in sync, so neither the model nor the HTML gets cluttered.
    

    

    

    🏛️Vue instance and MVVM
    10
    

    

    The Vue instance is Vue's ViewModel. Its data is bound to the view.
    

    WhyA common exam point: MVC and MVVM are not rivals. You can use both together.
    

    • Vue docs: “Although not strictly associated with the MVVM pattern, Vue’s design was partly inspired by it.”
    • Data binding: the data of the Vue instance is the “instance data”. An update to the data is reflected in the view. An update in the view can change the data.
    • MVC vs MVVM: it is NOT either-MVC-or-MVVM.
    • Controller: conveys actions to the model and calls the appropriate view based on the inputs and the model.
    • ViewModel: creates the framework for data binding. You can still use controllers to invoke actions.

    🧮Computed properties
    11
    

    

    Data derived from other data, updated automatically and cached.
    

    WhyDerived values stay correct with no manual updating, and they only recompute when something they use changes.
    

    • You often need derived data: take the original data and change it with some function or logic. Examples: an on/off boolean for styles from values in the data; navigation links based on history.
    • Each time the source data changes, the derived data is updated.
    • Computed properties auto-update and are cached based on their reactive dependencies: they recompute only when something they use changes.
    • Use one like plain data in the template: {{ fullName }}, no brackets. A method must be called, and it runs on every re-render.
    • A computed setter is also possible (see the Vue docs).

    🕵️Watchers
    12
    

    

    Run code when a specific value changes.
    

    WhyUse it for side effects like calling a server. For a plain derived value, a computed property is the better tool.
    

    • Watcher: explicitly look for changes in a value.
    • Can be used for imperative code: for more complex logic than just updating a property.
    • When possible, use a computed property instead of a watcher: more declarative, and cached.
    • Typical use: when query changes, ask the server for new results.

    ♻️Reuse and refactor
    13
    

    

    Write the repeated piece once. Use it many times.
    

    WhyFix a bug or restyle in one place instead of twenty.
    

    • DRY: Don't Repeat Yourself.
    • Examples: news items on the IITM front page; “People also bought” items on Amazon. Same structure and formatting, repeated.
    • Refactor: change code without changing functionality. Mainly for readability and maintainability, not for new features.
    • A component is Vue's way: one named, reusable piece with its own template, data and props.

    🧱Component structure
    14
    

    

    Props in, data inside, template out.
    

    WhyThese three parts are what you define for every component. Know them and most of Vue components is clear.
    

    • Properties (props): passed down from the parent to customise each instance.
    • Data: the individual data of the present instance. It also has its own watchers, computed properties etc.
    • Template: how to render. Render functions are possible (see the docs). Slots: see the next card.
    • Data flows down: parent to child through props. Treat props as read-only inside the child.

    Quick checkHow does a parent customise each instance of a component?
    Props are passed down from the parent. Each instance can get different values.
    

    

    

    🎰Templates and slots
    15
    

    

    {{ }} for text, safely. Slots for the content you pass in.
    

    WhyVue escapes text for you, which blocks a whole class of injection attacks.
    

    • Templates use {{ }}, similar to Jinja.
    • Safety features: it will not interpolate text into tags. Text is shown as plain text, never run as HTML, so a user-typed <script> cannot execute. It also reports errors on unclosed <div>s etc.
    • More complex render functions are possible. JSX mixes JS and HTML, similar to React.
    • Slot: the main element of text. Use the component like a regular tag, and what you put between the tags goes into the <slot>. Properties can be defined in the tag.

    ⚙️How does reactivity work?
    16
    

    

    Vue wraps each property in a getter and setter, so it knows when data is read or changed.
    

    WhyThis is the “magic” explained: no polling and no manual updates. Vue hears about a change the instant it happens.
    

    • To update the screen automatically, Vue must know when data is accessed and when it is modified.
    • How: add methods to objects. In JS everything is an object, so a property can get a getter and a setter with Object.defineProperty().
    • get runs when the property is read: the place to track who uses it. set runs when it is written: the place to trigger updates.
    • Example 1 just forwards reads and writes to the original data. Example 2 adds track() and trigger(): exactly the hooks Vue uses to re-render.
    • Vue 2 did this with defineProperty, as on the slides. Vue 3 uses Proxy for the same job.
